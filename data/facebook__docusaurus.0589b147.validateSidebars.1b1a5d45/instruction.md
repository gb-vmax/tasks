# Bug Report

### Describe the bug

When working with sidebars configuration, I'm encountering an issue where the sidebar validation logic seems to be processing the wrong data. Instead of validating the actual sidebar items, it appears to be trying to validate the sidebar IDs (keys) themselves.

### Reproduction

```js
const sidebars = {
  tutorialSidebar: [
    {
      type: 'category',
      label: 'Tutorial',
      items: ['hello', 'tutorial-basics/create-a-document'],
    },
  ],
  apiSidebar: [
    {
      type: 'autogenerated',
      dirName: 'api',
    },
  ],
};
```

When the validation runs, it attempts to iterate over the sidebar keys (like `'tutorialSidebar'`, `'apiSidebar'`) as if they were arrays, instead of iterating over the actual sidebar item arrays.

### Expected behavior

The validation should process the actual sidebar items (the arrays of sidebar item objects), not the sidebar IDs. Each sidebar item should be validated according to its type (category, doc, link, etc.).

### System Info
- Docusaurus version: latest
- Node version: 18.x

This seems like a regression that affects sidebar validation. The current behavior tries to call `forEach` on strings instead of the actual sidebar arrays.
