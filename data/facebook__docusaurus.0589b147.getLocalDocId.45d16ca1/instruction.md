# Bug Report

### Describe the bug

I'm experiencing an issue with document ID parsing in the autogenerated sidebars. When working with documents that have paths containing slashes, the sidebar generator is not correctly extracting the local document ID.

### Reproduction

```js
// Given a document with ID like: 'guides/getting-started/installation'
// The function should extract 'installation' (the last segment)

const docId = 'guides/getting-started/installation';
const localId = getLocalDocId(docId);

// Expected: 'installation'
// Actual: 'guides' (first segment instead of last)
```

This affects how documents are organized in the autogenerated sidebar structure. Instead of using the last part of the path as the local ID, it's now using the first part.

### Expected behavior

The `getLocalDocId` function should return the last segment of a document path (after the final `/`), not the first segment. For example:
- `'docs/intro'` should return `'intro'`
- `'guides/api/reference'` should return `'reference'`
- `'tutorial'` should return `'tutorial'`

### System Info
- Docusaurus version: latest
- Plugin: @docusaurus/plugin-content-docs
