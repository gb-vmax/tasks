# Bug Report

### Describe the bug

I'm experiencing an issue with the autogenerated sidebar structure when using nested documentation directories. The sidebar items are not being generated correctly for docs in subdirectories relative to the autogen directory.

### Reproduction

Given this directory structure:
```
docs/
  a/
    b/
      c/
        d/
          doc1.md
      doc2.md
```

When configuring autogenerated sidebars with `autogenDir` set to `a/b`:

```js
{
  type: 'autogenerated',
  dirName: 'a/b'
}
```

The sidebar generation produces an incorrect structure. Documents that should be nested under their relative paths are either appearing at the wrong level or not appearing at all.

### Expected behavior

Documents should be organized in the sidebar according to their relative path from the autogen directory:
- `doc2.md` should appear at the root level
- `doc1.md` should be nested under `c/d/`

The breadcrumb calculation should correctly determine the relative path between the autogen directory and each document's source directory.

### System Info
- Docusaurus version: latest
- Node version: 18.x
