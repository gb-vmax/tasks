# Bug Report

### Describe the bug

When using autogenerated sidebars with a specific `autogenDir`, documents that shouldn't be included are being added to the sidebar. This seems to affect cases where the autogenerated directory name is a prefix of another directory.

### Reproduction

Set up a docs structure like this:

```
docs/
├── api/
│   └── intro.md
├── api2/
│   └── other.md
└── guide/
    └── start.md
```

Configure autogenerated sidebar with `autogenDir: 'api'`:

```js
{
  type: 'autogenerated',
  dirName: 'api'
}
```

### Expected behavior

Only documents inside the `api/` directory should be included in the autogenerated sidebar. Documents in `api2/` should NOT be included since it's a different directory.

### Actual behavior

Documents from `api2/` are incorrectly being included in the sidebar along with documents from `api/`. The sidebar generation logic appears to be using a simple string prefix check instead of properly checking directory boundaries.

This breaks the expected isolation between different documentation sections.
