# Bug Report

### Describe the bug

I'm experiencing an issue with the autogenerated sidebar where nested category items are losing their `position` and `source` metadata prematurely. This causes the sorting to not work correctly for deeply nested sidebar structures.

### Reproduction

When using autogenerated sidebars with nested categories that have position metadata, the nested items don't maintain their sorting order as expected.

```js
// Example sidebar structure with positions
docs/
  category1/
    _category_.json (position: 1)
    subcategory/
      _category_.json (position: 2)
      doc1.md (position: 1)
      doc2.md (position: 2)
```

The nested documents and categories lose their position information during the sorting process, resulting in incorrect ordering in the final sidebar.

### Expected behavior

Nested sidebar items should be sorted according to their `position` and `source` metadata at each level of the hierarchy before the metadata is stripped away.

### System Info

- Docusaurus version: Latest
- Node version: 18.x
