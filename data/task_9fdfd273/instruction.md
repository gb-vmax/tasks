I'm a support engineer at a managed hosting company and a client has reported suspicious behavior on their Linux server. I need you to collect security diagnostics from the system and produce a structured report. The relevant diagnostic data has already been captured to files in `/home/user/diagnostics/` (the actual system commands couldn't be run due to permissions, so the data was pre-collected and saved to these files for offline analysis).

Here is what's in `/home/user/diagnostics/`:

- `open_ports.txt` — output of `ss -tlnp`, listing open TCP listening ports
- `processes.txt` — output of `ps aux`, listing running processes
- `crontabs.txt` — contents of `/etc/cron.d/` files concatenated, listing scheduled jobs
- `passwd.txt` — a copy of `/etc/passwd`
- `suid_files.txt` — output of `find / -perm -4000`, listing SUID binaries found on the system
- `file_perms.txt` — output of `ls -la` for several sensitive directories

Your job is to analyze these files and produce a security diagnostic report at `/home/user/report/security_report.txt`.

The report must have the following **exact** format:

```
=== SECURITY DIAGNOSTIC REPORT ===
Generated by: support-diagnostics v1.0

--- OPEN PORTS ---
Listening ports: <N>
Suspicious ports (not in: 22,80,443,3306,5432): <port1>,<port2>,...
(sorted numerically ascending, comma-separated, no spaces)
If none: Suspicious ports (not in: 22,80,443,3306,5432): NONE

--- PROCESSES ---
Total processes: <N>
Root processes: <N>
Suspicious process names: <name1>,<name2>,...
(processes whose command name matches any of: nc, ncat, netcat, socat, cryptominer, xmrig, minerd — sorted alphabetically, comma-separated, no spaces)
If none: Suspicious process names: NONE

--- CRONTAB ENTRIES ---
Total cron entries: <N>
(count only non-comment, non-blank lines across all crontab files)
Entries running as root: <N>
(lines where the username field — 6th whitespace-delimited token — is "root")
Suspicious cron commands: <N>
(lines where the command portion — everything after the 6th token — contains any of the strings: wget, curl, /tmp, base64, bash -i)

--- SUID BINARIES ---
Total SUID files: <N>
Non-standard SUID files: <path1>,<path2>,...
(paths NOT starting with /usr/bin, /usr/sbin, /bin, /sbin — sorted alphabetically, comma-separated, no spaces)
If none: Non-standard SUID files: NONE

--- PASSWD FILE ---
Total user accounts: <N>
(total lines that are not blank and not comments)

(usernames of accounts where 3rd colon-delimited field is "0", sorted alphabetically, comma-separated, no spaces)

--- RISK SUMMARY ---
Critical findings: <N>
(sum of: number of suspicious ports + number of suspicious process names + number of suspicious cron commands + number of non-standard SUID files + number of extra UID-0 accounts beyond "root" + number of accounts with empty passwords)
Risk level: <level>
(CRITICAL if Critical findings >= 5, HIGH if >= 3, MEDIUM if >= 1, LOW if 0)
```

Please analyze the diagnostic files and produce this report. Make sure every number and list is computed accurately from the actual file contents. The report file should be at `/home/user/report/security_report.txt`. Create the `/home/user/report/` directory if it does not exist.
