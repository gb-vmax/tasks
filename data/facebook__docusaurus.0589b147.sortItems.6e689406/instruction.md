# Bug Report

### Describe the bug

When using autogenerated sidebars with nested categories, the sorting behavior is not working as expected. The sidebar items appear to be sorted at the wrong level - parent categories are being sorted before their children are processed, which causes the final order to be incorrect.

### Reproduction

Create a docs structure with nested categories that have explicit position frontmatter:

```
docs/
  category-a/
    _category_.json (position: 2)
    doc1.md (position: 3)
    doc2.md (position: 1)
  category-b/
    _category_.json (position: 1)
    doc3.md (position: 2)
    doc4.md (position: 1)
```

With autogenerated sidebars enabled, the categories themselves get sorted correctly (category-b appears before category-a), but the documents within each category don't respect their position values properly.

### Expected behavior

The sidebar should:
1. Sort items at each level according to their position
2. Process nested categories recursively 
3. Maintain the correct order after removing position metadata

The items within each category should be sorted independently based on their position values, with the sorting happening after the recursive processing of nested items.

### System Info
- Docusaurus version: latest
- Node version: 18.x
