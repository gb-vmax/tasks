# Bug Report

### Describe the bug

When using autogenerated sidebars with `autogenDir: '.'`, all documents from the entire docs directory are being included in the sidebar generation, regardless of their actual location. This causes the sidebar to include docs that shouldn't be part of the autogenerated section.

### Reproduction

```js
// docusaurus.config.js or sidebar configuration
{
  type: 'autogenerated',
  dirName: '.' // Root directory
}
```

With the following docs structure:
```
docs/
  intro.md
  guide/
    getting-started.md
  api/
    reference.md
```

All documents (intro.md, getting-started.md, reference.md) are being included in the autogenerated sidebar, even when they should be filtered based on the directory structure.

### Expected behavior

When `autogenDir` is set to `'.'`, only documents that are actually in the root directory should be included, not all documents in subdirectories. The logic should properly distinguish between:
- Documents at the root of the autogen dir
- Documents in subdirectories when autogen dir is `'.'`
- Documents in subdirectories when autogen dir is a specific path

### System Info
- Docusaurus version: latest
- Node version: 18.x

This seems to be affecting sidebar generation logic where the filtering condition isn't working as expected for the root directory case.
