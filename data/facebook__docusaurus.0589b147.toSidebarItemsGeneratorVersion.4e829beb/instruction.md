# Bug Report

### Describe the bug

When using sidebar generators in a localized docs setup, the `version` object passed to the generator function has the wrong `contentPath` property. Instead of getting the localized content path, it seems to be using a non-localized path or the property is missing entirely.

This breaks sidebar generation for localized versions since the generator can't properly resolve document paths in the localized content directory.

### Reproduction

```js
// sidebars.js
module.exports = {
  docs: [
    {
      type: 'autogenerated',
      dirName: '.',
    },
  ],
};

// Custom sidebar generator
async function myGenerator({version, docs}) {
  console.log(version.contentPath); // Shows wrong path for localized versions
  // Generator logic that depends on contentPath fails for i18n
}
```

### Steps to reproduce
1. Set up a Docusaurus site with multiple locales (e.g., en, fr)
2. Create localized docs in `i18n/fr/docusaurus-plugin-content-docs/current/`
3. Use a custom sidebar items generator that accesses `version.contentPath`
4. The generator receives the wrong content path for the French locale

### Expected behavior

The `version` object passed to sidebar generators should contain the localized content path when generating sidebars for localized versions. For example, when generating sidebars for the French locale, `version.contentPath` should point to the French content directory.

### System Info
- Docusaurus version: latest
- Node version: 18.x
