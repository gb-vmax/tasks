# Bug Report

### Describe the bug

When using autogenerated sidebars with nested categories, the sidebar items are not being sorted correctly. The `position` frontmatter property seems to be ignored for items within nested categories, causing them to appear in an unexpected order.

### Reproduction

Given the following docs structure with position frontmatter:

```
docs/
  category1/
    doc1.md (position: 3)
    doc2.md (position: 1)
    doc3.md (position: 2)
```

With autogenerated sidebar configuration:
```js
{
  type: 'autogenerated',
  dirName: '.'
}
```

### Expected behavior

The docs should be ordered according to their `position` values: doc2, doc3, doc1

### Actual behavior

The docs appear in alphabetical order by filename instead, ignoring the position values in nested categories.

The position sorting works fine at the top level but breaks when dealing with nested category items.

### System Info
- Docusaurus version: latest
- Node version: 18.x
