# Bug Report

### Describe the bug

I'm experiencing an issue with autogenerated sidebars where the items are not being sorted correctly. When I have nested categories with position metadata, the sorting seems to be applied but then the original unsorted order is returned instead of the sorted items.

### Reproduction

```js
// docs structure with position frontmatter:
// - doc1.md (position: 3)
// - doc2.md (position: 1)
// - category/
//   - nested1.md (position: 2)
//   - nested2.md (position: 1)

// Expected sidebar order after autogeneration:
// 1. doc2
// 2. doc1 
// 3. category
//    - nested2
//    - nested1

// Actual result: items appear in original filesystem order, not sorted by position
```

The sidebar items are being processed and sorted internally, but the final output doesn't reflect the sorted order. It seems like the sorting is happening but then the wrong array is being returned.

### Expected behavior

Sidebar items should be ordered according to their `position` frontmatter value (and then by source path as a secondary sort). Nested categories should also have their children sorted recursively.

### System Info
- Docusaurus version: latest
- Node version: 18.x
