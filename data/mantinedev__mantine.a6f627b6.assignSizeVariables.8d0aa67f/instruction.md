# Bug Report

### Describe the bug

CSS variables generated by the default CSS variables resolver are being created with inverted key-value pairs. The variable names and their values are swapped, causing CSS variables to be incorrectly defined.

### Reproduction

```tsx
import { MantineProvider } from '@mantine/core';

function App() {
  return (
    <MantineProvider>
      {/* Components using size-based CSS variables */}
    </MantineProvider>
  );
}
```

When inspecting the generated CSS variables in the browser's DevTools, you'll see variables like:
```css
--mantine-spacing-xs: var(--mantine-xs-spacing);
```

Instead of the expected:
```css
--mantine-spacing-xs: <actual-value>;
```

The variable name and value are swapped - the actual size value becomes the CSS variable name, and the proper variable name becomes the value.

### Expected behavior

CSS variables should be generated correctly with the proper variable name as the key and the size value as the value:
```css
--mantine-spacing-xs: 10px;
--mantine-spacing-sm: 12px;
/* etc. */
```

### System Info
- @mantine/core version: latest
- Browser: Chrome/Firefox

This appears to affect all size-based CSS variables (spacing, font-size, etc.) generated by the default resolver.
